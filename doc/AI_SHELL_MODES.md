# AI 助手 Shell 执行模式

在 AI 助手设置的「Shell 工具 → 执行模式」切换。选择免确认模式时确认一次，之后不会逐条弹窗。已有配置不会自动升级权限；旧 enabled=true 仍映射到手动确认。

| 配置 mode | 行为 |
| --- | --- |
| off | 不提供工具 |
| confirm | 每条命令手动确认，以应用权限执行 |
| automatic | 仅自动放行原有只读网页抓取白名单，其余直接拒绝 |
| restricted | 自动执行，以 UID/GID 65533 执行，清空附加组、设置 no_new_privs，禁止重新取得 root |
| full | 自动执行，以应用权限运行；词典笔上通常是 root |

所有模式保留黑名单、8 KiB 命令上限、输出截断、并发/队列限制、取消和会话校验。所有免确认模式使用最小环境，并在超时配置为 0 时仍执行 10 秒超时。切换模式会取消所有旧的活动、排队和待确认命令，避免权限在排队期间改变。

受限模式在 /tmp 的随机目录下提供独立工作目录，跨命令保留，应用重启后不再复用。子进程降权失败时以 126 退出，绝不回退到 root。它限制文件大小为 16 MiB、文件描述符为 64、同 UID 进程数为 32，并禁用 core dump。

## 受限用户不是沙盒

它只使用 Linux 自主访问控制和禁止提权机制。仍可联网、读取所有公开可读文件、修改所有公开可写文件。设备上的用户分区可能缺少完整的 Unix 权限语义；实测 PenModsconfig.json 是 0666，因此受限用户也不能保护该配置文件。它也不隔离内核、挂载、网络、进程视图或阻止后台进程自行脱离进程组。不得将它描述为可安全执行不可信代码的沙盒。

真正的沙盒不需要 Docker，但需要针对设备内核验证 mount/PID/network namespace、只读根目录、设备节点隔离与 seccomp，并以隔离失败即拒绝执行为前提。目前未提供此模式。

AI 自动审批可以后续作为单独的审批策略，与执行权限组合；模型判断不构成系统安全边界，也无法保证抵御网页提示注入。目前未提供此模式，不会把主模型生成命令视作独立审查通过。

## 验证

主机策略回归（包括旧模式兼容、黑名单、大小/NUL 限制、复杂脚本和网页抓取策略）：

```sh
g++ -std=c++17 -Isrc tools/shell-policy/check.cpp src/shell/ShellCommandPolicy.cpp -o /tmp/shell-policy-check
/tmp/shell-policy-check
```

设备验证可用 Zig 交叉编译同一文件，普通运行检查策略；以 root 启动并传入 --drop 检查实际 UID/GID、附加组、no_new_privs、无法恢复 root 和 /etc/passwd 不可写。此探针不修改系统文件。
