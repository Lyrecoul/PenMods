# 播放器缩放过滤修复与设备性能定位

记录日期：2026-10-18。本轮修复缩放过滤，并测量普通模式的瓶颈；普通模式保留原有采样数量、采样位置和颜色转换。

以下行为与测量对应 v1.0.2 的最近邻缩放。v1.0.3 已将 `smooth` 与 `downsamplingEnabled` 解耦，页面改为 `downsamplingEnabled: !zoomMode`、`smooth: true`；GL 与 CPU 回退均保留双线性过滤。下表缩放组的测量不代表 v1.0.3。

## 行为与接入

- `VideoPlayer.downsamplingEnabled` 默认 `true`。关闭时，I420、NV12、External OES 使用独立的单次采样材质，片元着色器不包含多点采样循环。
- 继承的 `smooth` 控制纹理线性／最近邻采样；关闭降采样时，所有 GL 平面的 MIN/MAG 过滤都固定为 `GL_NEAREST`。
- 属性变化触发场景图更新。暂停切换材质时保留纹理、裁剪和颜色矩阵，恢复普通模式无需等待新帧。
- CPU 回退保留当前源帧。关闭过滤时按源尺寸转换 RGBA，再最近邻显示；恢复普通模式后使用原有显示尺寸转换。暂停切换也能取回源帧细节。
- 示例和实际页面都绑定 `downsamplingEnabled: !zoomMode`、`smooth: !zoomMode`。

## 测量时的临时诊断与口径

以下开关和指标仅用于记录本次测量方法。测量完成后，诊断实现、计数器、计时钩子与环境开关已从最终源码移除。

测量版本默认关闭诊断，在启动加载插件的进程之前设置：

```sh
FFPLAYER_DIAGNOSTICS=1
# 仅对照组额外设置；保留普通显示尺寸和线性过滤，仅移除 GL 多点采样：
FFPLAYER_DIAGNOSTIC_SINGLE_SAMPLE=1
```

每个播放器每 5 秒输出一条 `Video perf:` 汇总，停止时补一条尾段。指标为 `avg/max/total,n`，耗时单位 ms；分析稳态时丢弃预热和停止时的不足 5 秒尾段。

| 字段 | 含义与边界 |
| --- | --- |
| `decoder/source/fps/path/taps` | 当前解码器、素材尺寸、流声明帧率、实际渲染路径和每轴采样数；`taps=5` 为 25 个采样位置 |
| `decoded/published/replaced` | 成功解码帧数、交接给场景图的帧数、尚未被场景图消费就遭新帧覆盖的帧数 |
| `decode_late/present_late` | 解码回调／呈现阶段因过期而跳过的帧 |
| `decode` | `avcodec_send_packet` 与 `avcodec_receive_frame` 调用耗时，包含返回 EAGAIN 的调用；排除输出回调和队列等待，不等于整个解码器所有内部线程的 CPU 用量 |
| `queue_wait/present_wait/pending_wait` | 解码输出队列背压、音视频同步等待、待呈现帧交接至场景图消费的等待；暂停也可能计入队列等待 |
| `upload` | GL 上传／dma-buf 导入的主机调用耗时；不等于 GPU 后续执行耗时 |
| `convert` | CPU RGBA 转换及 Qt 纹理创建调用耗时；Qt 延迟提交的纹理上传反映在后续场景渲染中 |
| `uploaded` | 成功更新的视频帧／CPU 纹理次数；CPU 过滤切换时也会重新创建纹理 |
| `sync` | `updatePaintNode` 耗时，包含其中执行的上传或转换；不能和它们相加 |
| `scene_cpu/scene_gpu` | `beforeRendering` 至 `afterRendering` 的整场景主机提交耗时／GPU 耗时，包含同一 Qt Quick 窗口的其他内容；不是孤立视频绘制，也不计最终屏幕扫描输出 |
| `gpu_skipped/gpu_disjoint` | 查询槽耗尽／其他查询占用时跳过的次数，以及 GPU 计时失效时丢弃的样本数 |

GPU 仅在 `GL_EXT_disjoint_timer_query` 或桌面 `GL_ARB_timer_query` 支持时启用。8 个查询槽在后续帧检查结果是否就绪，不等待结果，不调用 `glFinish`。不支持时 GPU 样本数为 0，不能据此认为 GPU 不耗时。

计数器使用独立原子快照，GPU 查询也跨帧取回；相邻区间边界可能有一帧或一个样本的偏差。`uploaded / 区间秒数` 是视频帧更新速率，不等于屏幕实测刷新率。

| 设备 | AArch64，设备树型号 `Rockchip rk3326 for exam version`，Qt 5.15.2 / Wayland |
| GPU | OpenGL vendor `ARM`，renderer `Mali-TDVX`；支持异步场景查询 |

独立启动使用 `QT_QPA_PLATFORM=wayland`、`XDG_RUNTIME_DIR=/var/run` 和 `LD_LIBRARY_PATH=/userdisk/Qtlib/:/oem/YoudaoDictPen/output/libs`。最终复验显式选择设备已有的 `QT_WAYLAND_SHELL_INTEGRATION=xdg-shell-v6` 并唤醒屏幕。一次没有任何画面提交的运行已作废，不计入下表。

## 60 秒稳态结果

平均耗时按各区间的 total 和 n 加权汇总。

| 指标 | 普通模式 | 缩放模式 | 普通尺寸、单次线性采样诊断组 |
| --- | ---: | ---: | ---: |
| 统计时长（秒） | 60.009 | 60.001 | 60.001 |
| downsampling / smooth | true / true | false / false | true / true |
| 实际采样 | 5×5，线性 | 单次，最近邻 | 单次，线性 |
| 解码帧 / 发布帧 | 1800 / 1800 | 1800 / 1800 | 1800 / 1800 |
| 待呈现帧覆盖 | 750 | 0 | 0 |
| 视频更新次数 | 1051 | 1800 | 1800 |
| 视频更新速率（帧/秒） | 17.514 | 30.000 | 30.000 |
| 场景提交次数 | 1060 | 1800 | 1800 |
| 解码 API 平均 / 最大（ms） | 0.077 / 2.047 | 0.075 / 3.826 | 0.075 / 4.068 |
| 上传／导入平均 / 最大（ms） | 1.776 / 6.028 | 1.646 / 6.309 | 1.624 / 8.396 |
| 待呈现等待平均 / 最大（ms） | 16.599 / 35.728 | 0.892 / 5.640 | 0.911 / 9.366 |
| 场景主机提交平均 / 最大（ms） | 1.326 / 10.242 | 1.316 / 5.862 | 1.324 / 5.914 |
| 场景 GPU 平均 / 最大（ms） | 44.012 / 77.104 | 2.935 / 8.504 | 4.748 / 9.572 |
| GPU 样本数 | 1061 | 1800 | 1800 |
| GPU 跳过 / 失效样本 | 0 / 0 | 0 / 0 | 0 / 0 |
| 解码过期 / 呈现过期跳过 | 0 / 0 | 0 / 0 | 0 / 0 |

三组的解码输出队列背压平均约 33.04 ms，呈现同步等待平均约 33.2 ms，符合按 30 fps 调度；这些等待和解码 API 调用分开计量。

**结论：该设备、该素材、External OES 路径的普通模式主要受 GPU 多点采样限制。** 三组均能解码及发布 30 fps，上传／导入调用约 1.6–1.8 ms。保持普通尺寸与线性过滤，仅移除多点采样，场景 GPU 平均耗时从 44.0 ms 降至 4.75 ms，视频更新恢复 30 fps，待呈现覆盖从 750 降为 0。

该结果支持后续优先研究保持画质的 GPU 采样实现。本轮普通模式仍使用原有算法，不承诺消除其掉帧；诊断组改变了缩小滤波，仅用于区分瓶颈，不作为普通模式的优化方案。这里也没有把短时 NV12／CPU 功能复验外推为那些路径的 60 秒性能结论。

## 功能验证与交付

设备上的合成 I420、NV12 测试使用有 stride padding 的 642×360 图案，验证所有 GL 平面的实际 MIN/MAG 过滤、材质变体、单独修改 smooth、暂停反复切换、90°/180° 旋转、缩放平移与换帧。强制 CPU 后，同样覆盖 I420、NV12，并确认关闭过滤时纹理仍为源尺寸。均通过。

四条真实视频路径分别测试暂停后关闭过滤再恢复、旋转、平移、恢复播放、切换到另一段 640×360 视频：

| 路径 | 强制条件 | 暂停切换与像素恢复 | 切换视频 |
| --- | --- | --- | --- |
| External OES | 硬解、GL、零拷贝 | 最近邻画面发生变化，恢复后与原暂停截图逐像素一致 | `h264_rkmpp`，640×360，进度继续增长 |
| NV12 | 硬解，`FFPLAYER_ZEROCOPY=0` | 同上 | `h264_rkmpp`，640×360，进度继续增长 |
| I420 | `FFPLAYER_HWDEC=0` | 同上 | `h264`，640×360，进度继续增长 |
| CPU RGBA | `FFPLAYER_HWDEC=0 FFPLAYER_GL=0` | 同上 | `h264`，640×360，进度继续增长 |

视频切换素材为 `/userdisk/Music/01.mp4`。四组截图均为 320×170；同组恢复前后差异包围盒为空。该比较证明恢复本次普通模式帧的像素一致，修改前普通算法的一致性另外由源码对照确认。
