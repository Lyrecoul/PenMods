## 目标与判断

让歌词具备 SPlayer 的连续演唱反馈、稳定的当前句焦点、平滑换句和自由浏览体验，并适应 320×170 的词典笔屏幕。
采用原生 Qt Quick 实现。SPlayer 的 Vue/DOM/CSS 和 AMLL Web 渲染器不能直接作为 Qt Quick 组件使用；本计划复现其数据语义和视觉行为。

当前版本完成了 LRC 独立解析和同时间戳译文配对，但仍属于基础播放器：

- `LyricCue` 只有开始时间和文本边界；`lyricMarkup()` 在开始时整词变色，没有演唱进度。
- 当前行由宿主 `currentPos` 驱动，尚未量测宿主位置通知的间隔与抖动。
- `ListView` 只提供当前索引跟随，没有显式的自动跟随/用户浏览状态。
- 字号固定、非当前行统一透明度，缺少距离相关的视觉层次。
- `YAudioPlayerLrcMouseArea` 覆盖歌词区，点击会暂停，横向移动会快进/后退；它与歌词点选、纵向浏览有冲突。
- 同时间戳内容一律配对成翻译，尚不能表达对唱和重叠声部。

## 目标体验与初始参数

以下数值是原型起点，须由实机可读性与帧时间决定最终取值。

| 项目 | 目标行为 |
| --- | --- |
| 当前句 | 位于可用歌词区域约 42%–46% 高度；按实际多行高度定位，保留上下文 |
| 原文与译文 | 原文 20–22 px，译文 13–15 px；同一句作为整体布局和滚动；优先保证当前原文、译文完整可读 |
| 普通邻句 | 用同一排版字号，显示缩放约 0.94–0.97；按离焦点距离淡化，避免持续改变字号引发重新换行 |
| 连续高亮 | 已唱部分保持高亮，当前词内部连续扫过，未唱部分暗显；渐变边界可选 |
| 换句 | 约 280–420 ms 缓动；新目标接续当前速度/位置；较大 seek 立即落位 |
| 屏幕边缘 | 上下约 10–16 px 轻量渐隐；黑色背景先采用匹配背景的渐变覆盖，复杂背景才评估遮罩 |
| 超长句 | 自然换行，按视觉行更新高亮；超过可用高度时允许当前句内部跟随/浏览，避免整句缩小到不可读 |
| 译文 | 默认整句随原文激活。只有译文本身有词时间时才执行逐词效果，不套用原文节奏 |
| 间奏 | 有可靠结束时间时显示低成本三点提示；普通 LRC 不凭行间距断言上一句何时唱完 |

默认保留克制的行缩放与透明度变化。模糊、明显弹簧、逐词上浮作为后续可选效果，在基础帧率达标后评估。

## 模块方案

### 1. 统一歌词文档

扩展当前 `LyricTimeline`，由不可变的歌曲文档描述：

- 行 ID、开始/结束时间、原文、译文、音译。
- 每个词的开始/结束时间、文本范围、时间精度标记。
- 可选声部/背景歌词和关联 ID，使同时间戳译文与对唱不混淆。
- 明确区分源文件提供的结束时间、由下个标签推导的结束时间以及未知结束时间。

Enhanced LRC 从下一个词标签推导当前词结束；末尾空标签保留为明确结束点。最后一个词没有结束信息时降级处理，不能把漫长间奏全部当成拖音。
普通 LRC 保持逐句效果，不生成伪逐字时间。

译文精确时间戳优先匹配。外部翻译若启用容差对齐，必须一对一、可解释、有限窗口，不把一条译文重复匹配给相邻句；先以精确匹配作为默认。

逐步将 `QVariantList` 改为静态行数据的 `QAbstractListModel`。播放时只改变时钟和活跃状态，不重新生成整首歌词列表。
官方 JSON 模型保留为跟读/复读适配层；新显示逻辑由独立模型负责。

### 2. 歌词播放时钟

新增 `LyricPlaybackClock`，集中处理宿主位置、播放状态、倍速、seek、曲目标识和显示偏移。

- 用 `QElapsedTimer` 在两次宿主位置采样之间估算显示位置；音频位置仍由宿主决定。
- 先量测采样周期，再确定漂移校正阈值与插值上限；不直接照抄 Android 的阈值。
- 小误差平滑校正；显式 seek、切歌、播放结束立即重置基准和动画。
- 暂停冻结演唱进度；恢复时重新建立基准；缓冲或位置长期不更新时限制外推。
- 歌词偏移只改变显示映射，点句跳转反向使用相同映射，防止多加一次 offset。
- 用歌曲代号丢弃旧歌的延迟结果和回调。
- 可见且播放时以约 30 fps 驱动显示；隐藏时停止视觉帧更新，重新显示时直接校准当前位置。
- GUI 属性更新留在 GUI 线程，不从 scene graph 渲染回调直接修改 QObject/QML 状态。

### 3. 连续歌词绘制

先做一个只含长句、换行、中英混排和逐字时间的小型原型，对比：

1. QML 双层文字加视觉行裁切：验证效果和实现成本。
2. C++ `QQuickItem` 配合 `QTextLayout` 排版缓存、scene graph 纹理/几何和进度遮罩：作为需要精细控制时的正式实现候选。

选择标准是实机表现。长句跨行时不能拿“整句总宽度 × 进度”当高亮宽度，也不能把字节/UTF-16 下标当成视觉字符位置。
排版必须处理 grapheme、emoji、组合字符、连字和双向文本；映射高亮到实际视觉片段。

静态文本排版与纹理在加载、宽度/字体变化时缓存。每帧主要更新当前词进度和少量几何/材质参数，避免反复拼接 RichText、重排整句或重绘整张图片。
只保留可见行和少量邻行的渲染缓存；场景失效时正确释放/重建图形资源。

### 4. 布局、滚动和交互

将宿主耦合的大型歌词组件逐步拆成可独立验证的 `LyricViewport`、`LyricLineDelegate` 和控制层。

显式区分：

- 自动跟随：定位当前句，允许换句过渡。
- 用户浏览：手指拖动期间停止自动居中，歌词高亮仍随音频更新。
- 等待恢复：手指释放且惯性滚动结束后约 3 秒恢复，或点击“回到当前句”。
- 跳转重定位：取消过时滚动目标和词动画，立即同步到实际位置。

移除覆盖整块歌词的“点击即暂停”拦截。建议单击歌词行跳到实际发声时间并播放；播放/暂停交给独立控件。纵向手势浏览歌词，进度条承担定位，原有横向快进/后退手势迁移到专用控制区域。
触摸抖动阈值需实机调节；拖动、惯性停止和点句不能互相误触。禁止仅靠 `preventStealing` 布尔设置解决手势竞争。

左侧常驻控制栏可在沉浸模式中收窄/收起，但返回与播放入口必须保持可发现，触摸目标建议不少于约 28–32 px。

| --- | --- | --- |

| P1：时间轴与连续高亮 | 词起止时间、明确末尾标签、显示时钟、暂停/倍速/seek 校准 | 长词内部连续推进；暂停冻结；反向跳转立即恢复正确进度 |
| P2：完整视觉组件 | 焦点布局、行缩放与淡化、边缘渐隐、长句处理、滚动控制器、浏览与点句交互 | 手动浏览不被抢回；点句不误暂停；双语长句完整可读。这一阶段形成主要体验交付 |
| P3：歌词来源与格式 | YRC 与常见方括号逐字 LRC；TTML 子集；原文/译文/音译；下载链路保留词时间 | 文件发现、匹配、解析、保存、重载全链路工作，不只是解析器识别扩展名 |
| P4：高级效果与调优 | 可靠间奏三点、可选弹簧/微上浮；有依据的声部/背景歌词；性能分档 | 基础模式达标后，逐项启用效果并给出实机开销 |

P3 需要同步更新 `FileManager` 的配对歌词扫描、隐藏侧挂歌词逻辑和 `MusicPlayer` 的候选路径选择。
在线歌词已改用支持 YRC 的接口，预览后保存 Enhanced LRC，保留词时间与译文；没有有效 YRC 时回退 LRC。
设备离线时网络失败保留重试入口；本次主机已验证真实响应往返，设备端在线验收因 DNS 不可用待用户联网后完成。
TTML 初期明确支持子集（行/词时间、译文、音译及可识别声部），限制 XML 大小与解析深度、不解析外部实体。加密/压缩 KRC/QRC 另行评估，不能仅更换扩展名就宣称支持。

## 验证与性能目标

以下是待实机验证的目标，不是当前已有测量结论：

- 默认模式目标稳定 30 fps，播放阶段帧时间 P95 尽量不超过 33 ms；记录均值、P95 和长帧，不只凭截图判断。
- 正常采样条件下，显示时间与宿主采样校准后的误差目标不超过 100 ms；不将音频解码/seek 本身的延迟计入绘制延迟。
- 歌词数据已就绪后首次排版与显示以 200 ms 内为初始目标；超长文件不得长时间阻塞 UI。
- 渲染缓存新增内存以约 8 MiB 内为初始预算；随可见区域受控，不随全曲字数生成全部词对象/纹理。
- 页面隐藏后不保留歌词视觉刷新循环。默认不开模糊；必要时保留逐字语义、降低视觉效果。

固定样例至少包含：普通 LRC、同时间戳双语、多条译文、Enhanced LRC 的明确/缺失结束标签、长拖音、跨行英文词、中文/emoji/组合字符、前奏、间奏、重复段、负 offset、乱序标签、异常时间、长曲、对唱样例。

纯逻辑测试覆盖解析、时钟与状态转换。实机由维护者操作：播放/暂停/倍速、前后 seek、连续切歌、浏览后恢复、点句、横竖排版边界、左右手模式和回归跟读/复读。
代理负责构建、资源一致性、部署哈希、只读日志和性能数据检查，不执行触摸注入。

每个混合修改阶段同时生成资源并构建主库/资源库；采用临时文件加重命名部署。逐阶段保留可回退版本，不叠加未验证的重效果。
